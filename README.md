# AI Locman

Мобильная AI-студия разработки: Android-клиент + TypeScript backend + OpenRouter.

> Стартовый каркас v0.2.0. Это MVP foundation, не production-релиз и пока не автономный программист.

## Текущий состав проекта

- Android-клиент на Kotlin + Jetpack Compose с отдельными экранами проектов, истории, памяти и фоновых задач.
- История диалогов восстанавливается после перезапуска; в Backend-режиме хранится в PostgreSQL, в Local AI — в локальном хранилище приложения.
- Память проекта разделена на архитектуру, решения и знания; она подмешивается в контекст модели и не смешивается между проектами.
- Каталог OpenRouter с поиском и настройкой модели отдельно для каждого проекта.
- GitHub App integration с привязкой репозитория к проекту, просмотром веток, файлов, коммитов, PR, Actions и diff. GitHub-доступ агента остаётся read-only.
- Потоковая выдача токенов в Local AI режиме.
- TypeScript/Fastify API, PostgreSQL и Redis/BullMQ.
- Фоновый worker для задач Backend-режима: планирование, read-only исследование репозитория, журнал событий, независимое ревью и отмена.
- Базовая политика исполнения команд, fail-closed sandbox controller и хранилище одноразовых подтверждений, привязанных к commit и diff. Реального sandbox runtime пока нет, поэтому выполнение команд выключено.
- Серверная парольная аутентификация для одного self-hosted владельца: opaque bearer-сессии, хранение только SHA-256-хэшей, срок действия 30 дней, отзыв текущей или всех сессий владельца. Android хранит сессию в EncryptedSharedPreferences и передаёт её API.
- Content-addressed хранилище артефактов с SHA-256-проверкой, лимитами и owner-scoped API списка/скачивания. Приём артефактов от runner и retention/GC ещё не реализованы.
- Docker Compose для локальной инфраструктуры и GitHub Actions для проверок backend и сборки Android.

## Следующие этапы

1. Реальный rootless sandbox runtime на отдельном хосте: изоляция задач, лимиты ресурсов, запрет сети по умолчанию, отмена и гарантированная очистка.
2. Хранилище артефактов с лимитами размера, хэшированием, проверкой содержимого и сроком хранения.
3. Переход от текущей однопользовательской парольной защиты к полноценной multi-user идентификации, разграничению пользователей и прав; после этого — защищённые GitHub write/PR workflows и экран подтверждения в Android.
4. Backend streaming, reconnect, вложения и push notifications.
5. Полная проверка Android UI на эмуляторе и устройстве, включая системные отступы и клавиатуру.

## Безопасность и локальный запуск

Текущий MVP использует один пароль доступа (`LOCMAN_ACCESS_PASSWORD`) и фиксированный owner ID (`LOCMAN_OWNER_ID`). Это защищает API от анонимного доступа, но не является multi-user авторизацией и не подходит для публичного production-размещения. Пароль должен быть уникальным и не короче 12 символов; backend отказывается запускаться без него. Android хранит bearer-сессию в Android Keystore-backed EncryptedSharedPreferences. Сессии имеют срок 30 дней и могут быть отозваны при выходе. Пять неверных попыток с одного IP блокируют вход на 15 минут.

Backend и worker запускаются только при явно заданном `NODE_ENV=development` или `NODE_ENV=test`; production и unset environment завершаются с ошибкой. Docker Compose задаёт development mode и публикует порты только на loopback (`127.0.0.1`). Не меняйте эту привязку на публичный интерфейс.

Перед удалённым развёртыванием обязательны TLS, полноценная multi-user идентификация, разграничение доступа, защита от перебора пароля и безопасное хранение секретов. Не подключайте Docker socket к API или обычному agent-worker. Команды остаются заблокированными до развёртывания и проверки отдельного изолированного runtime.

Подробности: `docs/AUTHENTICATION.md`, `build-workers/EXECUTION_CONTRACT.md`, `docs/ARCHITECTURE.md`, `docs/IMPLEMENTATION_PLAN.md` и `docs/SECURITY_MODEL.md`.
